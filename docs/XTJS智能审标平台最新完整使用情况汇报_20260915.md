# XTJS 智能审标平台建设与使用情况汇报

**更新日期：2026 年 9 月 15 日｜统计时点：20:06，北京时间**

适用对象：项目经办人、审查人员、业务负责人及平台管理员。
本报告更新 9 月 13 日版本，依据当前生产数据库的只读统计、留存日志、线上健康状态及截至本次发布的验收记录编制。

## 一、总体使用情况

平台已具备“上传材料—分阶段 OCR—智能审查—证据预览—人工复核—报告导出”的完整辅助审标流程。当前保留 **18 个项目、63 组投标材料**，关联的 **144 份文件全部完成 OCR**；18 个项目均保存了商务标形式审查、偏离检查、商务标查重、技术标查重、人员复用检查的结果记录。

当前前端、后端和 GPU 推理服务在线，后端、Redis 及 vLLM 健康检查正常。最近一轮改进重点是减少明确证据被错误理解、避免状态和文件归属不一致，以及让上传、替换、OCR 失败能够被使用人员看见并处理。

**当前适合用于辅助筛查和人工核验，尚不能作为无人复核的最终评审结论。** 已有结果记录不等于每个子项完成，也不等于人工确认无误；待复核和风险提示不能直接等同于真实违规。近期修复没有自动重算全部历史结果，旧页面中的部分提示仍可能来自旧规则。

## 二、统计口径与较上版变化

- 在用项目：数据库中未逻辑删除的项目；累计数包含历史测试、重复提交及已删除项目，不等于独立采购业务数量。
- 投标组：项目内的材料关联组，不是跨项目去重后的企业数。同名、同材料的不同项目分别计数。
- 文件：按文档标识去重；容量按记录的原件字节数汇总，采用十进制 GB，不含全部 OCR、副本、结果和历史对象的存储开销。
- 审查覆盖：按已保存结果的模块键统计。本次没有下载并逐条核验全部结果正文，也没有触发新一轮分析或 OCR。
- 输入版本一致：表示结果记录对应当前材料版本，**不表示历史结果已由最新算法生成**。
- 日志：本次可读取记录覆盖 2026-08-10 至 2026-09-15，最新日志时间约为北京时间 19:54；包含人工操作、自动轮询、运维检查和回归验证。

## 四、现有功能与实际使用方式

| 功能区域 | 当前支持能力 | 使用注意事项 |
|---|---|---|
| 项目管理 | 文件夹上传、成组上传、招标/商务/技术文件关联、列表与详情 | 核对每家单位商务标和技术标对应关系 |
| 上传恢复 | 展示预期上传清单、失败文件和未完成关联；手动补传、重试关联 | 上传不完整时先补齐，再继续识别和检查 |
| 分阶段 OCR | 招标、商务、技术阶段处理；完成数和实时页进度；技术标范围选择 | 已完成文件可跳过；并非所有中断都自动恢复 |
| 单文件替换 | 文件行“替换文件”；三种文件角色均支持 | 新文件识别成功后才替换关联，不必删除整个项目 |
| 商务标形式审查 | 完整性、模板一致性、报价合理性、分项报价、签章日期 | 材料存在、正文符合、签章符合分别判断 |
| 偏离检查 | 招标实质 ★ 条款，以及投标主动填写的负偏离、部分满足 | 主动负偏离不再因无 ★ 条款而跳过；复杂语义仍需复核 |
| 商务/技术查重 | 文本及相关证据的重复线索、聚类展示 | 公共模板相同不能单独证明串标或抄标 |
| 人员复用 | 提取候选名单、人工修正和确认、确认后核验复用 | 名单未确认不等于没有人员复用 |
| 独立招标审查 | 单独上传招标 PDF、查看异常/待复核/通过及历史记录 | 与项目投标审查分开统计 |
| 结果审核 | 问题筛选、双方 PDF 定位、人工编辑保存、候选位置提示 | 未定位、歧义与已定位但正文不同应区别处理 |
| 报告输出 | Word、JSON 等既有结果导出能力 | 先确认复核内容；材料过期结果不能作为当前报告导出 |
| 账号管理 | 登录、改密、管理员用户管理、登录失败保护 | 业务岗位权限尚未细分到所有操作 |

### 4.1 推荐操作流程

1. 准备可正常打开、页面完整的 PDF，确认招标文件和每家投标材料的归属。
2. 创建项目并上传；发现“上传不完整”时，按清单补传或重试关联。
3. 完成招标、商务 OCR，生成商务审查；再按项目范围继续技术 OCR 和专项检查。
4. 对失败文件查看原因：暂时超时可重试；原件无法读取时单独替换有效 PDF。
5. 到分析中心执行需要的检查，到结果审核查看对应原文、候选位置和计算依据。
6. 完成人工复核及人员名单确认；修改材料后，按提示重新检查受影响结果。
7. 导出并登记最终报告，保留原件及复核依据。

### 4.2 新增的失败与替换体验

| 页面状态 | 实际含义 | 可采取的操作 |
|---|---|---|
| 上传不完整 | 预期文件尚未上传或关联完成 | 手动补传、重试关联 |
| 排队等待 | 已存在排队任务，尚未开始该文件 | 等待队列调度 |
| 识别中 | 有当前文件的实时进度 | 查看页数和进度 |
| 识别失败 | 本轮发生已记录异常 | 查看原因、失败时间，重试或替换文件 |
| 未完成，待继续 | 尚未识别完成，当前未在排队 | 手动继续 OCR；可能是此前任务中断 |
| 状态暂时无法确认 | 进度接口查询失败 | 等待查询重试，不能据此认定 OCR 正常或结束 |
| 已完成 | 已有识别结果 | 继续业务审查；不代表审查合格 |

OCR 失败原因现在会持久保存，刷新或重启后仍可查看；识别成功后清除。页面发现本轮失败且任务已结束时停止等待，恢复操作入口。数据库也不可用等情况可能无法保存文件级原因，此时页面展示状态查询异常，不能把未知状态当作成功。

替换文件时，先上传并识别新 PDF，再原子更新当前项目关联；失败或材料版本冲突时保留旧关联。旧文件、旧 OCR 和结果对象保留，其他仍引用旧文件的项目不受影响。若响应丢失，页面提示“替换未确认完成”，应以刷新后的文件列表确认实际状态。

## 六、近期已经发布的改进

### 6.1 上传、存储与状态一致性

- 共享 ECS 临时凭证缓存、到期前刷新和有限重试；已预建存储桶不再逐次探测。分片取消权限补齐后，真实上传、下载校验与失败会话取消已验证。
- 已引用对象读取失败时明确报错，不作为空结果覆盖；人工副本和结果采用新对象键，数据库提交成功后切换引用。
- 项目输入版本随材料关联变化维护；旧任务不能覆盖新输入状态，新版本单项重跑不把其他旧项恢复成当前有效结果。
- 并发补传使用位置租约、请求标识和唯一约束；上传期间不长期持有数据库事务锁。
- 停用通用 OSS 物理删除入口，保留业务逻辑删除和本次上传失败回滚，避免绕过引用检查误删文件。
- 轻量列表、详情和 OCR 元数据查询减少重复读取大对象；同步 I/O 使用受限线程池。

### 6.2 形式审查与证据定位

- 金额保留元、万元、亿元等单位；使用精确换算。区分年度、合同全周期、单价和包件口径，依据不足待复核。
- 费率阈值以适用招标规则为准，取消默认 1.5% 和固定折扣率阈值；限价区分明确金额、明确不设、无法确定。
- 截止日期支持明确更正关系，补充“提交响应文件截止时间”字段；日期摘要依据实际适用附件统计。
- 修正正文引用被误当附件边界、同页附件混入其他签字要求、坐标解释错误及单一签字被重复使用。
- 分项金额不再从型号中取数字；恢复明确合价、附加税费等依据，部分行未解析时保留待复核，不以部分求和直接判定合计错误。
- 商务组成保留续行和明确可选属性；“如有”只作用于确切附件，不将局部可选说明扩展为整份材料免检。
- 模板与签章共用可靠附件定位，区分父级章节、资格证明、授权委托和身份证附属材料；候选冲突不强行选第一项。
- “许可证或备案证明”恢复完整条款并按选择组检查；目录只作查找线索，不作为已提供正文的证明。
- 双方证据保留文档归属；无投标位置时明确显示未定位，歧义候选分别展示，防止另一投标人的文件覆盖当前预览。

### 6.3 偏离、名称和会话安全

- 偏离表填写说明与实际响应分开，避免模板指令中的“不满足”被当成投标人的主动负偏离；2026-249 已核实的真实主动负偏离仍保留。
- 单位名称区分展示原文与比较名称，保留括号地区内容；印章存在与主体一致分别判断，通用公司后缀不能证明主体一致。
- 切换项目时隔离结果、编辑和预览归属，加载失败不显示上一项目结果。
- OpenAPI 改用虚构静态示例；改密增加令牌版本，使旧令牌失效。
- 单文件替换和 OCR 失败持久展示已在最新版本发布。

以上是已发布行为与已验证样本的结论，不表示对所有版式或所有历史告警均已验证无误。没有增加 OCR 自动纠字，也没有将全部完整性检查统一改为标题相似度匹配。

## 七、尚需人工处理或继续完善的问题

| 类别 | 当前判断及限制 | 当前处理方式 |
|---|---|---|
| 单价报价及限价引用覆盖 | 2026-241 等历史核验曾发现单价被归到费率、具体限价或单位关联不足；后续验收未证明这些场景已全部闭环 | 核对报价类别、列头、计量单位及适用限价，保留待复核 |
| 偏离语义和适用范围 | 星标图例、评分规则、条件性承诺曾触发伪响应；包件专属要求混用未在已发布记录中完成全面验收 | 优先核对条款所属包件、文字角色与投标人实际承诺，不套用全部条款 |
| 模板正文与标题差异 | “投标/磋商”、福利性“单位/企业”、断行填空仍可能导致对齐不确定 | 对照原件人工确认，不自动替换为等价表达 |
| 表单歧义与复杂材料条件 | 同名多候选、直接投标/委托投标条件交叉，无法可靠确定时仍待复核 | 不按序号或出现顺序强行匹配；不把未定位直接当真实缺件 |
| OCR 原始误识别 | 印章遮挡、扫描模糊、缺字、金额行丢失可能影响结论 | 核对原件、使用人工复核或有效新文件；不自动纠字 |
| 人员名单与摘要 | 历史样本将“工作态度”等误提为人名；待确认名单可能显示“0 项” | 必须先确认名单，不能把候选为空或未确认解释为无复用 |
| 查重证据的业务含义 | 公共模板、证照说明、统一承诺重复不等于抄标；同文件双角色处理仍按已确认范围暂缓 | 人工区分公共内容与实质方案雷同，保留证据来源 |
| 单位展示回退 | 无可靠名称时仍可能回退文件名，部分长名称需确认 | 不把文件名兜底视作已确认企业主体 |
| 大结果页面加载 | 八一项目历史重试曾约 65.45 秒；旧快照完整结果解码约 347.2 MiB，技术查重聚合约 306.5 MiB | 按需加载和聚合减重尚未完成本轮验收，不能宣称慢加载已根除，也不能直接归因 OSS |
| 自动恢复及历史归档 | 可人工续传、继续 OCR；未新增可靠的自动任务恢复队列；未自动物理回收历史对象 | 保持手动恢复与引用核对，避免盲目删数据或全量重算 |

正常分页、同页放多个附件、正文正常引用附件，以及 OCR 将标题分类为正文，属于平台应适配的正常情况，**不应要求招标人仅为消除系统误报而改写文件**。原件确有措辞差异或内容缺损时，作为文件事实复核，不因新的编制规范倒推历史材料不合格。
