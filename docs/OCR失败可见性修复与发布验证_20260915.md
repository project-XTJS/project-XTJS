# OCR 失败可见性修复与发布验证

日期：2026-09-15

## 原因

已有文件识别失败时，异常只写后台日志；实时进度在任务结束后清除。状态接口仅保留 extracted=false，前端将所有未完成文件显示为“待处理”。手动继续 OCR 后，页面只等 parsing_status 达到目标，失败仍可能等待至超时。

## 本次修改

- 文档新增 `ocr_last_error`，包含安全的错误类型、说明及失败时间。已存在文件的识别入口持久记录异常，不将对象地址、凭据或堆栈返回为公开原因。
- 文件行区分已完成、识别中、识别失败、排队等待及未完成待继续。失败行显示原因，项目当前状态和提示区同时提醒；保留上次状态，避免请求刷新期间文件行消失。
- 失败元数据持久保存，刷新和重启后仍可查询。成功 OCR 在同一事务清除错误；迟到失败不得标记已识别或已删除的文件。保留错误期间重试的实时进度优先展示。
- OCR 轮询发现当前目标阶段有失败且任务已结束时结束等待，恢复操作按钮。未完成且连续两次观察到没有排队或活动任务时，提示可能中断，可手动继续。
- 状态查询异常显示“当前进度暂时无法确认”，不静默清空。跨项目响应不能显示为当前项目进度。
- 不修改 OCR 原文、材料关联、业务判断及历史结果。不自动重新 OCR。

涉及文件：`app/service/ocr_failure.py`、`app/service/document_ingest_service.py`、`app/service/postgresql_service.py`、`app/router/postgresql_batch.py`；前端 `src/pages/ProjectsPage.jsx`、`src/App.css`。

## 验证

- 平台单测：225 项通过，包含错误分类、失败持久化调用、存储失败、取消、失败可续跑及成功文件屏蔽旧错误。
- 浏览器测试：22 项通过，包含错误原因展示、失败后结束等待、刷新后保留错误、重试进度、成功清除错误、状态查询失败及现有文件替换/项目切换/预览回归。
- 隔离 PostgreSQL 集成：通过。验证新连接读取失败记录、输入版本和结果引用不变、失败重试保留记录、成功重试清除记录、迟到失败及删除保护；原有替换和人工保存检查通过。
- Flyway 已应用并验证 `V20260915180000__persist_ocr_failure.sql`，为可空的兼容字段。
- 线上 18 个有效项目 OCR 状态接口均通过；核验时无未识别文件、无排队任务。
- 发布前后 18 个项目输入版本、解析状态及历史结果引用一致；线上前端资源和后端修改文件与源码一致。
