# 三类识别匹配修复与发布验证

日期：2026-09-15。状态：已实施、验证并发布。

## 实施范围

1. **附件标题与证据定位**：模板和签章检查共用附件候选、边界及定位结果。支持正文类型标题、明确标题前缀与正文合块、相邻块中的完整标题。保留 OCR 原文、原页码和已有坐标；没有行坐标时保留块级定位。可靠定位后继续检查实际正文，不再因正文不同而清空投标预览。
2. **表单身份与层级**：区分资格证明、授权委托、身份证附属材料及章节容器。具体标题、已有完整别名优先；候选冲突和分差不足保留待复核，不通过其他回退路径强行选择。正常的同一表单连续标题仍合并；身份证粘贴说明、落款字段和跨页续写字段不切断表单。
3. **材料关系**：在明确的商务组成区域恢复同条续行，保留单项、任一满足、全部满足和关系不明状态。“许可证或备案证明”按一组检查，目录仅作线索；未提交的替代分支不再独立补成必交模板。复杂条件不作自动推理。
4. **预览归属保护**：实际浏览器回放发现，原角色索引包含所有投标人，同角色的后一个文件可能覆盖当前投标人。现限定为当前投标人与招标文件。未定位只展示招标依据；歧义候选分别标注“待确认”，不将任一候选作为已匹配正文。

没有修改数据库结构、公共接口、OCR 原文、OCR 纠字、全局完整性相似度阈值、报价和日期比较算法。此前已存在的分项报价改动不属于本次新增修复。

## 验证结果

- 平台 `unittest`：**216 项通过**，其中本次新增 29 项针对性用例。覆盖正文标题、合块、连续标题、父子表单、身份证附属材料、相同候选及顺序反转、回退链、真实正文修改、同块/跨块/跨页选择组、明确“且”、真实缺件、仅目录出现、表单续页和落款边界。
- 浏览器回归：**4 项通过**，覆盖缺附件、已定位附件、歧义候选及其他投标人干扰。
- 实际 262 项目回放结果在浏览器中生成 **127 条展示记录**，核验目标表单的文档归属和页码；跨投标人归属断言通过。这是实际结果的预览生成验证，没有重新上传或运行生产 OCR。
- 隔离 PostgreSQL 集成：人工保存、再次保存、重新读取通过；新增定位依据、材料选择组和人工意见保留，历史结果与 OCR 对象引用不变。测试使用独立数据库及内存对象存储，未写入生产项目。
- 多项目离线回放：**18 个项目、63 份商务标全部完成，无执行错误**。包含 262、位育、2026-249及现有历史样本。新旧版本使用同一批 OCR/人工副本输入，均禁用外部嵌入调用以隔离比较；本轮没有验证外部模型重新 OCR 的效果。
- 63 份样本均通过输入内容哈希检查，OCR 输入没有被改写。最终回放中，没有出现已定位表单的日期从旧版 `pass` 退化为新版 `missing_date` 的情况。
- 前端生产构建、代码编译、差异空白检查通过。

## 回放变化及保留限制

差异清单记录 **377 次模块明细变化**，包含位置、检查范围、状态和选择组结构变化；不代表发现了 377 个文件错误，同一附件可在两个检查模块分别计入。

| 变化原因 | 明细数 |
|---|---:|
| 正文标题、具体表单优先级、父子层级或边界恢复，证据位置变化 | 178 |
| 候选冲突或分差不足，取消强制匹配，保留待复核 | 72 |
| 严格表单身份校验未通过，保留未定位 | 29 |
| 有效区段变化，重新统计签章和日期依据 | 32 |
| 恢复续行和材料关系，按组检查 | 34 |
| 取消重复或不适用检查项 | 17 |
| 定位与正文符合性分别判断后，继续核验实际正文 | 11 |
| 恢复完整标题或边界后增加有效检查项 | 4 |

需要注意以下变化，不能按“通过数量减少”直接认定新版本误报，也不能据此认定文件不合格：

- 部分历史授权书原先匹配到了资格证明或历史合同中的签字字段，新版不再沿用这种对应。
- 通用偏离表对应多个商务/技术子表、同名重复表单或标题分差不足时保留待复核，不按出现顺序选第一份。
- “其他”与“其他材料”、“供应商基本情况表”与招标中的完整表名等未达到既有完整别名或匹配阈值的情况，仍可能未定位。本轮没有增加别名或降低阈值，需要人工确认；未定位不是已经证实未提交。
- 条件交叉的“直接投标应提供……；委托投标应提供……”保留关系不明确状态，不把找到其中一个材料自动当作整条要求通过。完整性分数可能因此下降；这些项在归一化及抽数表中列为待复核，不作为确定缺件。
- 正文固定措辞差异、模板对齐不确定等原有人工复核事项继续保留，没有为消除告警而放宽正文规则。
