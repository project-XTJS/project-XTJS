# 招标文件审核需求（修订版）

> 基于真实招标文件核查结果修订。判定统一为三态：
> **通过(pass)** / **不通过(fail，有确凿依据)** / **待人工复核(unclear，信息缺失或无法自动核对)**。
> unclear 不是失败，是"系统给不出确定结论"，输出中必须说明**缺了什么、人工要核什么**。

## 1. 项目预算与最高限价

- **业务约定：预算与最高限价视为同一概念（同义词）**。
- 核对内容：文档中"预算/限价"声明是否**自洽**——单一来源即视为该值（通过）；多处出现时应一致。
- 两者都出现且**预算低于限价** → 不通过（文档自相矛盾）。
- 支持"最高投标限价同预算/等于预算"类表述。
- 未识别到任何预算/限价 → 待人工复核。
- 限价口径包括：最高限价、最高投标限价、招标控制价、总限价等；"单价限价/包干费上限"等非总价表述不参与。

## 2. 最高限价一致性

- 核对招标公告、投标人须知、报价章节中出现的**总限价**是否一致。
- 多包件/多标段：各包件限价不同属正常设计 → **按包件人工核对**（待复核），不判冲突。
- 只有一处来源出现限价 → 待复核（来源不齐）。
- 单价限价、超时包干费上限等非总限价金额，不参与一致性比较。

## 3. 投标保证金比例合规性

- 法规口径：《招标投标法实施条例》第 26 条——保证金**不超过项目估算价的 2%**。
- 实际执行：**按文档声明口径计算**——文档给出"限价的 X%"/"预算的 X%"/"估算价的 X%"，就按对应分母计算；只有金额时，优先用限价、其次预算/估算价作分母。
- 多包件：按包件分别核对（每包件保证金 vs 每包件限价/预算）。
- 明确"不收取/免收/无须提交"（含复选框勾选状态）→ 通过。
- 复选框中"□不收取 ■收取"应按**收取**处理；无法确定勾选状态 → 待复核。
- 有金额但无任何可作分母的限价/预算 → 待复核。

## 4. 履约保证金一致性（前附表 vs 合同）

- 两处描述（比例/基数/金额/免收）一致 → 通过；不一致 → 不通过。
- 文档明确"不设置/不收取/免收/无需缴纳"履约保证金 → **通过**（无需两处都有）。
- 一处有、一处无，或描述无法提取出可比较要素 → 待复核。

## 5. 付款方式一致性（前附表 / 技术需求 / 合同）

- 存在多处的：付款节点+比例一致 → 通过；不一致 → 不通过。
- 仅在一处出现，或某来源缺失付款方式 → 标注**缺失/待复核**，不视为不一致。
- 只有描述无具体比例（如"以最终合同约定为准"）→ 待复核。
- 中标服务费/费率阶梯表等非付款方式内容，不得当作付款方式参与比对。

## 6. 评标办法

### 6.1 大类构成

- 核对"**识别到的全部分值大类之和 = 总分**"，**不限定必须是商务+技术+价格三类**。
- 常见合法结构：
  - 商务 + 技术 两类（价格按"权值/系数"公式计分，不设价格分大类）；
  - 商务 + 技术 + 价格 三类；
  - 含资信/经济/其他附加类目。
- 缺类处理：已识别大类合计 = 总分 → 提示缺类（可视为通过，除非细项无法核对）；合计 ≠ 总分 → 不通过。

### 6.2 细项加总

- 每个大类下，细项的**单项满分**加总 = 大类分值（区间型取区间上限、扣分型取最高扣分）。
- 评分表跨页/跨表拆分时，需**合并后**核对；仅解析出部分细项时 → **待人工复核**，不得用部分细项判不通过。
- 类别总分行（如"（二）技术部分得分 70"）不算细项，不得重复计入。

### 6.3 分值区间

- 反向区间（start > end）→ 不通过。
- 同一评分项内**重复区间**、**重叠区间** → 不通过。
- **相邻区间（如 0-6 与 7-14）不算断层**；仅当存在真实空档（后区间起点 > 前区间终点 + 1）才算断层 → 不通过。
- 年份/编号/日期（2025-2027、XTJS2025-263）不得被当作分值区间。
- 不同评分项使用相同区间是正常的，不判重复。

## 推进建议

1. **先自动、后人工**：第 1/2/3 项金额类自动核对置信度最高，先跑；第 4/5 项一致性次之；第 6 项最复杂，先大类后细项。
2. **unclear 必须可行动**：每条待复核结论输出"缺什么 + 原文证据 + 人工要核对什么"。
3. **不误伤**：信息不足时一律"待复核"，只有证据确凿才判"不通过"。
