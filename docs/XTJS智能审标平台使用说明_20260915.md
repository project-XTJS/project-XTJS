# XTJS 智能审标平台使用说明

**版本：V2.0｜更新日期：2026 年 9 月 15 日**

适用人员：项目经办人、审查人员及账号管理员。
本说明按当前平台页面和已发布功能编写，重点介绍操作步骤、结果理解和异常处理。可独立于《平台建设与使用情况汇报》使用。

## 一、首次使用快速指南

**准备 PDF → 创建并上传 → 完成招标和商务 OCR → 生成商务审查 → 完成技术 OCR → 执行专项检查 → 核对原文及人工复核 → 导出报告。**

| 要做的事 | 进入页面 | 主要入口 |
|---|---|---|
| 上传完整项目 | 项目管理 | 新建项目 |
| 补齐上传失败的文件 | 项目管理 | 上传不完整提示中的补传入口 |
| 更换一份已有文件 | 项目管理 → OCR 进度 | 对应文件行“替换文件” |
| 继续未完成识别 | 项目管理 | 进行招标文件 OCR／进行商务标 OCR／继续技术标 OCR |
| 执行审查 | 分析中心 | 选择项目、勾选服务后“执行选中服务” |
| 查看原文和处理问题 | 结果审核 | 问题卡片、PDF 预览、人工处理按钮 |
| 核对人员名单 | 结果审核 | 人员抽取确认 → 确认名单并查重 |
| 下载审查报告 | 结果审核 | 导出入口 → 导出 Word 报告／导出 JSON |
| 只检查一份招标文件 | 招标文件审查 | 开始审查 |
| 管理账号 | 用户管理 | 仅管理员可用 |

“完成 OCR”表示已有识别内容；“有审查结果”表示已有程序输出；“人工确认”表示核对原件后的业务判断。这三个状态不能互相代替。

## 二、登录与材料准备

### 2.1 登录和退出

1. 在 Chrome 或 Edge 中打开单位提供的平台地址。
2. 输入分配的用户名、密码并登录。
3. 确认顶部显示“API 已连接”，进入“项目管理”。
4. 使用完毕点击“退出登录”。

忘记密码或账号被锁定时联系管理员。管理员重置密码后，原有登录会话会失效，需使用新密码重新登录。不要将密码、令牌或带临时签名的下载地址写入故障反馈。

### 2.2 上传前检查

- 使用 PDF；先在本地打开，确认能够正常翻页、没有缺页或密码保护。
- 一个项目对应正确的招标文件，每家投标人的商务标、技术标分别放入对应位置。
- 文件名包含单位名称及“商务”“技术”等角色信息，避免只命名为“扫描件”“文件”。
- 项目名称尽量采用“项目编号＋项目简称”；出现同名冲突时先确认是不是已有项目，不要重复上传同一业务。
- 扫描件应清晰、方向正确，印章遮挡、模糊和缺字可能影响识别。

**同一份合并 PDF 同时作为商务标和技术标上传，可能扩大查重范围或带来重复计数；当前未完成双角色专项优化。** 已有分册时按分册上传；只有合并文件时，应先确认使用范围，并对重复及人员结果人工核对。

### 2.3 文件夹上传结构

```text
XTJS2026-XXX 项目简称/
├── 招标文件.pdf
├── 投标人甲/
│   ├── 投标人甲-商务响应文件.pdf
│   └── 投标人甲-技术响应文件.pdf
├── 投标人乙/
│   ├── 投标人乙-商务响应文件.pdf
│   └── 投标人乙-技术响应文件.pdf
└── 投标人丙/
    ├── 投标人丙-商务响应文件.pdf
    └── 投标人丙-技术响应文件.pdf
```

选择最外层项目文件夹。顶层放招标 PDF；每个一级子文件夹代表一家投标人，内部放该单位的商务标和技术标。上传完成后仍应检查系统实际绑定结果。

## 三、创建项目与上传

### 3.1 方式一：上传整个项目文件夹

1. 进入“项目管理”，点击“新建项目”。
2. 在“一键上传整个项目文件夹”区域点击“选择项目文件夹”。
3. 选择按上述结构准备的根文件夹，等待上传和关联完成。
4. 检查项目名称、投标组数，以及每组招标、商务、技术文件是否正确。
5. 若出现文件作者等属性预警，核对涉及文件；相同作者或制作工具只是线索，不是串标结论。
6. 上传完整后，按页面按钮从招标文件 OCR 开始继续操作。

**文件夹上传完成不等于已经执行 OCR。** 以文件行状态和当前阶段按钮为准。

### 3.2 方式二：手动逐组上传

1. 点击“新建项目”，填写项目名称。
2. 选择一份招标文件。
3. 在“标书组 1”选择同一家单位的商务标和技术标。
4. 点击“添加一组”，继续添加其他投标人。
5. 核对每组文件归属，保持“分阶段审查”模式。
6. 点击“创建并执行 OCR”，等待页面提示。

手动创建成功后，系统会继续招标文件 OCR、商务标 OCR，并自动生成商务标形式审查结果。**偏离、人员复用及查重不是这一步全部自动完成**，后续到分析中心执行。

若提示“项目已创建，后续流程未完成”，应在已有项目中查看并继续，不必重新创建整个项目。

### 3.3 上传不完整时补传

1. 在项目列表选择原项目，查看“上传不完整，请补齐以下材料后继续检查”。
2. 找到缺失的单位和文件，在对应补传入口选择原计划上传的 PDF。
3. 补传文件需符合清单中的文件名要求。需要使用不同版本或不同文件名替换已有文件时，使用第四节的“替换文件”。
4. 如果文件已经上传、只是关联未完成，点击“重试关联已上传文件”。
5. 等待提示材料已补齐，再手动继续 OCR。

旧项目可能没有完整的预期上传清单。页面没有补传位置时，应联系管理员核对；不要自行假定文件已经齐全。两个浏览器同时补传同一位置被拒绝时，先刷新确认已有任务和文件状态，再决定是否重试。

## 四、单独替换一份文件

**适用情形：** 上传了错误版本、原 PDF 损坏或不可读取、需要更换当前项目的一份招标文件或投标文件。通常不需要删除整个项目。

1. 进入“项目管理”，选择目标项目。
2. 在“OCR 进度”中找到要更换的文件，核对文件角色和单位名称。
3. 点击该文件行右侧“替换文件”，选择本地可正常打开的新 PDF。
4. 页面显示“替换中…”后保持页面打开，等待上传和识别。
5. 成功后检查文件列表中的新文件名及完成状态。
6. 到分析中心重新执行本项目需要的审查，核对结果后重新导出报告。

招标、商务、技术文件均可替换；已识别文件和未完成文件均支持。项目正进行 OCR、当前页面正在执行其他操作或详情未加载完成时，入口暂时禁用。

### 替换结果如何确认

| 提示或情况 | 含义与处理 |
|---|---|
| 已识别并替换成功 | 新 PDF 已识别，并已关联到当前项目；继续重新检查 |
| 新 PDF 识别失败 | 原关联保留；先检查新 PDF 是否有效，再重试 |
| 材料发生变化／版本冲突 | 上传期间其他操作改变了项目；刷新后核对再操作 |
| 替换未确认完成／网络中断 | 不一定代表服务端未成功；先查看刷新后的文件列表，避免重复替换 |
| 替换按钮不可用 | 先等当前任务结束，或完成项目详情加载 |

替换成功后旧文件和旧结果保留，不物理删除；当前项目使用新文件。其他仍引用旧文件的项目不随之更换。同一招标文件在当前项目多个投标组中共用时，对应关联一起更新。

**替换成功不等于旧审查结果已经更新。** 仅重新执行一个检查，不会自动使其他旧检查恢复为当前有效结果。

## 五、OCR 操作与进度理解

OCR 是将 PDF 转成后续审查可使用的文字、表格和位置等信息。

### 5.1 按阶段继续

| 当前进度 | 下一步操作 |
|---|---|
| 已上传，但招标文件未完成 OCR | 点击“进行招标文件 OCR” |
| 招标文件完成，商务标尚未完成 | 点击“进行商务标 OCR” |
| 商务标完成，但没有商务形式审查结果 | 点击“生成商务审查”，或到分析中心执行商务标形式审查 |
| 已有商务审查，技术标未完成 | 确认技术标范围后点击“继续技术标 OCR” |
| 技术标完成 | 到分析中心执行尚需进行的专项检查 |

手动创建项目时，前面几个步骤可能已自动执行；不要重复点击已经完成的阶段。

### 5.2 选择技术标 OCR 范围

1. 商务阶段完成后，在项目详情查看“技术标 OCR 范围”。
2. 逐份核对单位及商务、技术文件名。
3. 按业务确定的范围选择参与 OCR 的技术标，至少保留一份。
4. 点击“继续技术标 OCR”。

取消勾选是调整本次参与范围，不是删除原文件。不要仅为消除失败提示而排除本应审查的单位。已保存范围尚未加载完成时，先等待加载或点击“重试加载”。

### 5.3 文件行状态

| 显示状态 | 说明 | 处理方式 |
|---|---|---|
| 排队等待 | 任务已加入队列，文件尚未开始 | 等待，不重复提交 |
| 识别中／页码进度 | 正在处理当前文件 | 查看当前页和进度变化 |
| 识别失败 | 已发生并记录异常 | 阅读该行的原因及失败时间，按原因处理 |
| 未完成，待继续 | 尚未完成且当前没有排队任务 | 使用当前阶段 OCR 按钮继续 |
| 状态获取失败 | 暂时无法查询后台状态 | 等待查询重试；不能据此判断任务已经停止 |
| 已完成 | 已保存识别内容 | 可进入下一步审查，不代表文件业务合格 |

失败原因会保留，刷新后仍可查看；成功重试后清除。页面确认本轮失败且任务结束后，会停止等待并恢复操作入口。没有活动任务却尚未完成时，可能需要人工继续，系统不保证自动恢复所有中断任务。

### 5.4 失败后选择重试还是替换

- **PDF 无法解析、可能损坏或不完整：** 在本地打开原件确认，换用有效 PDF，通过“替换文件”处理。
- **读取或识别超时：** 可以在任务结束后重试；持续失败时反馈管理员。
- **存储权限被拒、找不到原文件、服务资源不足：** 按提示联系管理员核对，问题处理后再继续。
- **页面加载失败：** 先重试加载或查询状态，不直接认定文件损坏。

继续 OCR 会跳过已完成文档。若异常再次出现，不要通过连续点击或反复创建项目解决。

## 六、执行智能审查

1. 进入“分析中心”，选择正确项目。
2. 查看当前可执行的审查项；未满足 OCR 条件的项目会被禁用。
3. 勾选本次需要执行的服务，可用“全选”选择当前可执行项。
4. 点击“执行选中服务”。
5. 等待执行结束，检查各卡片状态和错误提示。
6. 进入“结果审核”核对输出。

| 审查服务 | 前提 | 核对重点 |
|---|---|---|
| 商务标形式审查 | 招标和商务 OCR 完成 | 材料完整性、模板一致性、报价、分项报价、签章日期 |
| 偏离项目审查 | 商务 OCR 完成 | 招标实质 ★ 要求，以及投标主动填写的负偏离、部分满足 |
| 商务标查重 | 商务 OCR 完成 | 分项报价和相关偏离等商务内容的重复线索 |
| 人员复用审查 | 技术 OCR 完成 | 人员名单提取，人工确认后检查跨文件重名 |
| 技术标查重 | 技术 OCR 完成 | 技术材料之间的重复内容和对应证据 |

商务阶段可以先执行偏离检查；技术标就绪后，如需纳入其材料，应重新执行相关检查。偏离检查不是对所有非星标技术条款的全面实质评审；页面部分历史说明出现的“★/△”不应被理解为两者均已按相同规则完整覆盖。

“执行完成”仅表示程序完成本次处理，不等于所有子项通过。执行失败时先看具体服务提示，确认状态后重试该项，不必重复 OCR 全部文件。

## 七、阅读结果与核对 PDF

### 7.1 查找需要处理的条目

1. 进入“结果审核”，确认项目名称。
2. 在左侧按检查类型、文件或通过／未通过等条件筛选。
3. 打开具体条目，核对投标单位、要求、系统判断和对应文件。
4. 查看招标要求和投标响应原文，再作人工处理。

切换项目后如加载失败，点击重试入口。不要根据上一项目的记忆或旧报告处理当前条目。

### 7.2 常见结论的含义

| 结论或提示 | 应如何理解 |
|---|---|
| 通过 | 本次规则下未发现该项问题，仍需结合审查范围理解 |
| 未通过／失败／缺失 | 系统提示存在差异或未找到依据，需核对原文，不能一概视为真实违规 |
| 待复核 | 单位、范围、日期、标题或正文依据不足或冲突，需要人工确认 |
| 不适用／可选未提供 | 招标明确允许的情况下跳过，不算已通过的实质检查 |
| 未定位到对应投标内容 | 系统未取得可靠投标位置，不等于已经证实没有提交 |
| 对应附件待确认 | 有多个候选或归属不明确，逐一核对，不能直接选第一份 |
| 需重新检查／结果过期 | 当前材料变化后，旧结果不能直接用于当前报告 |

### 7.3 预览与页码

- 双方预览分别显示招标文件和当前投标人的文件，先核对文件名。
- 页码是**上传 PDF 的物理页码**，可能与纸面印刷页码或目录页码不同。
- 使用“跳到”、上一页、下一页及缩放按钮查看上下文。
- 高亮框是辅助位置；有时只能定位到较大的版面块，并非精确文字框。
- 若只显示招标预览，先查看是否提示未定位或待确认，再在投标 PDF 中查找实际材料。
- 预览失败或无法看清时，使用“下载 PDF”核对原件。

正常分页、同页多个附件、正文引用和标题被 OCR 分类为正文，都不能单独认定为文件编制错误。目录提到某材料，也不能单独证明该材料正文已经提交。

## 八、人工复核与人员确认

### 8.1 对系统条目作人工判断

核对原件后，按当前条目使用以下按钮：

| 按钮 | 用途 |
|---|---|
| 忽略此项 | 确认该告警不成立，按人工通过处理 |
| 确认保留 | 确认该问题需要保留 |
| 确认无误 | 对原通过项作人工确认 |
| 归为有错误项 | 将原通过项标记为需要保留的问题 |

等待操作返回，再核对条目状态；出现失败提示时不要当作已经保存。不要把“忽略”作为批量消除未核验告警的方式。

### 8.2 商务识别内容回填：当前入口限制

“识别内容回填”区域可查看 OCR 值、当前值，部分字段支持“修改”“完成编辑”和“恢复OCR”。

**当前核对的页面中，该面板尚未接入可用的保存／二次审查按钮。“完成编辑”只结束字段编辑，不能视为内容已经保存或结论已更新。** 如需持久修改这些识别值，应记录对应文件、页码和正确内容，联系平台管理员协助处理；不要依赖未保存草稿完成报告。

“恢复OCR”是恢复字段原识别值，不是重新运行 OCR。平台不自动纠正 OCR 字符；原件与人工判断应分别留存。此限制针对商务识别值回填，不等同于人员草稿或偏离状态不能保存。

### 8.3 偏离响应人工确认

有对应操作入口的星标响应条目，可使用“标记已响应”或“标记未响应”。点击后等待保存成功提示，重新核对结果。

投标文件中真实写明的“负偏离／部分满足”不能因其他行写“无偏离”而直接忽略。条件性承诺、模板填写说明或评分规则被误当响应时，应结合完整条款人工判断。

### 8.4 人员名单确认

1. 打开“人员抽取确认”。
2. 按单位和文件核对姓名、岗位及原文页码。
3. 修改错误候选，删除非人名或不属于本次申报的条目，按原件补齐遗漏人员。
4. 编辑会自动保存草稿；观察“草稿保存中／草稿待保存／草稿已保存”，确认保存成功。
5. 点击“确认名单并查重”。
6. 等待名单确认及重名检查完成，再核对跨文件人员结果。

**草稿已保存不等于名单已确认；“0 项”也不能代替确认步骤。** 同名不必然为同一人，应结合单位、岗位和证明材料判断。

## 九、导出报告

### 9.1 导出步骤

1. 确认选中正确项目，所需审查已有结果。
2. 检查是否有结果过期提示；材料替换后先重新检查。
3. 完成必要的人工复核和人员名单确认。
4. 打开导出入口，查看弹窗中的导出项和处理说明。
5. 点击“导出 Word 报告”或“导出 JSON”。
6. 下载后打开，核对项目名、单位名单、文件归属、关键结论及人工状态。

Word 适合阅读和业务归档；JSON 用于结构化留存或系统处理。当前导出说明为：导出全部审查结果，忽略项标为通过，保留项标为不通过，其他保持原状态。因此，不要仅因左侧隐藏了某类条目，就认为它一定不会进入报告。

### 9.2 报告更新与归档

- 下载到本地的报告不会随系统重审自动更新。材料或复核结论变化后重新导出。
- 文件名可采用“项目编号－审查报告－日期－版本”，避免新旧混淆。
- 结果未成功加载或已过期时，先处理页面提示，不使用旧报告冒充当前版本。
- PDF 属性中的作者、创建程序等为空，不表示正文缺失；相同工具或模板也不能单独作为串标结论。

## 十、单独审查招标文件

不需要上传各家投标文件、只想检查招标 PDF 时，使用“招标文件审查”。

1. 进入该页面，选择待审查 PDF。
2. 点击“开始审查”，等待完成。
3. 在历史列表选择本次记录，按异常、待复核、通过等条件查看。
4. 点击有定位依据的条目，核对原 PDF。
5. 对同一材料需要再执行时点击“重新审查”；换新原件时重新上传新 PDF。

该页面的记录独立于项目投标审查。删除或重新审查前核对文件名和目标记录，不把它当成某家投标人的响应材料。

## 十一、常见问题与处理

| 遇到的问题 | 建议操作 |
|---|---|
| API 连接失败 | 点击顶部“刷新”；仍失败时记录时间和提示，联系管理员 |
| 项目详情加载超时 | 点击“重试加载”；大结果可能需要更长时间，暂不判定为文件或 OSS 故障 |
| 上传失败，项目已经出现在列表 | 打开原项目检查缺失清单，补传或重试关联 |
| OCR 一直没有完成 | 看文件行是排队、识别中、失败还是待继续，按第五节处理 |
| PDF 无法解析 | 本地检查 PDF，使用“替换文件”上传有效原件 |
| 只错了一份技术标 | 替换该文件即可，通常不需要重传整个项目 |
| 替换后结果仍旧 | 到分析中心重新执行需要的审查，再核对并导出 |
| 替换请求超时，但不确定是否成功 | 先刷新文件列表确认当前关联，不立即重复替换 |
| “继续技术标 OCR”不可点击 | 核对商务 OCR、商务审查结果、范围加载及是否至少选择一份技术标；等待当前操作结束 |
| 单位名称识别不正确 | 核对原件名称、文件名与投标组配对；无法自行处理时反馈管理员，不自动替换形近字 |
| 只有招标文件预览 | 查看未定位／候选提示，在投标 PDF 中核对正文，不把招标页当投标证据 |
| 授权书与资格证明对应不清 | 按具体表单标题和正文核对，身份证页不能单独替代授权书 |
| 日期存在仍提示异常 | 对照有效截止日期、落款日期和适用附件；多日期或延期冲突可能需复核 |
| 报价被提示超限或不一致 | 核对元／万元、年度／全周期、单价、包件及分项是否完整，不只看摘要 |
| 重复文本很多 | 先排除公共模板、证照说明等公共内容，核对真正的方案重复 |
| 人员检查显示 0 项 | 先确认是否已完成“确认名单并查重”，不能把未确认当无复用 |
| 修改后没有生效 | 区分字段编辑、草稿保存、人工确认和重新检查；商务回填另见第 8.2 节限制 |
| 更新程序后历史问题仍显示 | 历史结果不自动全部重算；按需手动重新检查后核对 |

页面显示失败后，普通业务用户按提示重试或联系管理员即可，无需自行重启 GPU、vLLM 或数据库服务。

## 十二、账号、删除及问题反馈

### 12.1 管理员账号操作

管理员在“用户管理”中可创建账号、调整展示名或权限等级、启用／停用、重置密码及删除账号。系统保护当前账号和最后一个启用管理员，相关操作可能被拒绝。

普通、中级、高级账号目前没有覆盖所有业务操作的细分权限差异。项目删除、范围调整和报告确认仍应按单位分工执行。

### 12.2 删除项目

只需修复一份文件时优先替换，不通过删除整个项目处理单文件错误。确需删除时，先核对项目名称和需要保留的报告，再点击“删除项目”并确认。

项目删除为逻辑删除，不等于立即清除全部原件和历史对象，也不要将其视为业务用户可随时自助恢复的回收站。

### 12.3 联系管理员时提供什么

可直接按下面格式记录，方便定位：

```text
项目名称／项目标识：
发生时间：
所在页面和操作按钮：
涉及单位、文件名及文件角色：
PDF 物理页码（如有）：
页面完整错误提示：
预期情况与实际情况：
已尝试的操作及结果：
```

必要时附问题页面截图。金额、日期、签章或附件定位争议，应同时指出招标依据与投标原文位置。凭据、个人敏感信息和原件仅通过单位认可的渠道提供。
