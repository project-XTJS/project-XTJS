# XTJS 智能审标平台用户手册

文档版本：V1.0  
编制日期：2026 年 9 月 7 日  
适用系统：信投建设智能审标平台（XTJS）

## 1. 手册说明

本手册面向项目经办人、审查人员和系统管理员，说明如何从上传招投标文件开始，完成 OCR、智能审查、人工复核和报告导出。

系统输出属于智能辅助审查意见。OCR、规则和模型可能因扫描质量、文件版式或业务表述产生误报和漏报，最终结论必须由具备相应职责的人员结合原始文件确认。

## 2. 使用前准备

### 2.1 推荐环境

- 使用较新版本的 Chrome 或 Microsoft Edge。
- 通过单位提供的系统地址访问，例如 `http://服务器地址/`。
- 上传期间保持浏览器窗口和网络连接稳定。
- 仅上传获得授权的招投标文件，不在非受控设备留存敏感报告。

页面顶部显示“API 已连接”时，表示前后端连接正常；若显示“API 连接失败”，先点击“刷新”，仍失败则联系管理员。

### 2.2 文件准备原则

1. 当前项目文件应为 PDF。
2. 一个项目使用唯一且可识别的项目名称，推荐“项目编号 + 项目简称”。
3. 招标文件只能作为招标文件上传，不要混入投标文件组。
4. 每家投标人的商务标和技术标必须一一对应。
5. 文件名应包含单位名称及“商务”或“技术”等标识。
6. 扫描件应方向正确、页面完整、文字清楚；模糊、倒置和缺页会影响 OCR。
7. 不要重复使用“响应文件”等宽泛文件夹名创建不同项目。同名项目会被系统拒绝，以防文件串入已有项目。

### 2.3 推荐文件夹结构

使用“一键上传整个项目文件夹”时，按以下结构准备：

```text
XTJS2026-241 真实场景语音数据采购/
├── XTJS2026-241 真实场景语音数据采购 定稿.pdf
├── 投标人甲/
│   ├── 投标人甲-商务响应文件.pdf
│   └── 投标人甲-技术响应文件.pdf
├── 投标人乙/
│   ├── 投标人乙-商务响应文件.pdf
│   └── 投标人乙-技术响应文件.pdf
└── 投标人丙/
    ├── 投标人丙-商务响应文件.pdf
    └── 投标人丙-技术响应文件.pdf
```

文件夹名作为项目名；顶层 PDF 作为招标文件；每个一级子文件夹代表一家投标人，内部放该单位的商务标和技术标。

## 3. 登录和账号

### 3.1 登录

1. 打开系统地址。
2. 输入管理员分配的用户名和密码。
3. 点击“登录”。
4. 登录成功后默认进入“项目管理”。

连续多次输入错误密码会触发临时锁定。遇到锁定提示时，请等待锁定时间结束或联系管理员。

### 3.2 权限说明

系统账号显示四个等级：普通用户、中级用户、高级用户、管理员。

当前版本中：

- 所有已登录账号均可进入项目管理、招标文件审查、分析中心和结果审核。
- 只有管理员可进入“用户管理”。
- 普通、中级、高级三个等级目前未实施更细的业务功能差异，属于后续扩展预留。

### 3.3 退出

操作完成后点击右上角“退出登录”。在公共或共享电脑上不要仅关闭浏览器页面。

## 4. 页面导航

| 页面 | 用途 |
| --- | --- |
| 项目管理 | 创建项目、上传文件、查看绑定、执行分阶段 OCR、选择技术标范围 |
| 招标文件审查 | 单独审查招标 PDF，查看历史、异常、待复核和通过项 |
| 分析中心 | 选择项目并执行商务标形式审查、偏离、人员、商务查重和技术查重 |
| 结果审核 | 查看问题、PDF 高亮定位、人工修正、人员确认及报告导出 |
| 用户管理 | 管理员创建、停用、改级、重置密码和删除账号 |

## 5. 标准项目审查流程

### 5.1 流程概览

```text
准备 PDF
  ↓
创建项目并绑定招标/商务/技术文件
  ↓
招标文件 OCR → 商务标 OCR → 商务阶段审查
  ↓
选择参与范围 → 技术标 OCR
  ↓
执行偏离、人员复用及查重
  ↓
结果审核、PDF 定位和人工复核
  ↓
导出 Word 项目审查报告或 JSON
```

### 5.2 创建项目：文件夹上传

1. 进入“项目管理”。
2. 点击“新建项目”。
3. 在“一键上传整个项目文件夹”区域点击“选择项目文件夹”。
4. 选择按第 2.3 节准备的根文件夹。
5. 等待结构校验、上传和自动绑定完成。
6. 检查系统显示的项目名称、招标文件和每家投标人的商务标、技术标是否正确。
7. 如出现作者属性冲突预警，核对涉及单位和文件。该提示是风险线索，不等同于串标结论。
8. 文件夹上传完成后，按页面按钮依次执行招标文件 OCR、商务标 OCR 和后续流程。

如果提示项目已存在，请修改本次根文件夹名称后重新上传。系统不会把文件自动追加到同名项目。

### 5.3 创建项目：手工上传

1. 点击“新建项目”。
2. 输入唯一的项目名称。
3. 上传一份招标文件。
4. 在“标书组 1”上传同一家投标人的商务标和技术标。
5. 点击“添加一组”，继续添加其他投标人。
6. 逐组核对商务标与技术标是否属于同一家单位。
7. 点击“创建并执行 OCR”。

手工创建成功后，系统会启动招标文件和商务标 OCR，并生成商务阶段审查结果。若自动流程因网络或服务中断未完成，可在项目详情中按阶段按钮继续执行。

“并行组数”当前保留为兼容设置，后端统一按串行文档队列处理，通常保持默认值即可。

### 5.4 OCR 阶段和状态

项目解析状态按以下阶段推进：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 已上传/状态 0 | 文件已绑定，OCR 未完成 | 执行招标文件 OCR |
| 状态 1 | 招标文件 OCR 完成 | 执行商务标 OCR |
| 状态 2 | 商务标 OCR 完成 | 可执行商务阶段审查，选择技术标范围 |
| 状态 3 | 技术标 OCR 完成 | 可执行全部技术阶段专项审查 |

OCR 期间页面展示当前文件、页码和进度。大文件处理时间较长，不要因页面暂时没有结果而重复创建项目。

若 OCR 中断：

1. 刷新项目状态。
2. 查看哪个阶段和文件仍为待处理。
3. 点击当前阶段的继续按钮。
4. 系统应跳过已完成文档，只处理未完成部分。

### 5.5 选择技术标 OCR 范围

商务标 OCR 完成后，项目详情会显示“技术标 OCR 范围”：

1. 检查每家投标人的单位名、商务标和技术标名称。
2. 取消勾选不参与本次技术审查的技术标。
3. 至少保留一份技术标。
4. 点击“继续技术标 OCR”。

被剔除的范围会保存到项目工作流状态，后续分析应以保存后的范围为准。

## 6. 招标文件独立审查

“招标文件审查”适用于不创建完整项目、只检查一份招标文件的场景。

1. 进入“招标文件审查”。
2. 上传 PDF。
3. 点击“开始审查”。
4. 在审查历史中选择本次记录。
5. 使用“全部、异常、待复核、通过”筛选结果。
6. 点击有证据位置的条目查看原 PDF 页面和高亮内容。
7. 如规则或文件更新，点击“重新审查”。
8. 删除历史前确认文件名和目标记录。

该页面的记录与完整项目工作流用途不同，不要把独立招标审查记录误认为某个项目的投标文件。

## 7. 分析中心

### 7.1 选择项目

进入“分析中心”后先选择项目。页面会根据 OCR 状态自动禁用尚不满足条件的审查项。

### 7.2 审查项目与执行条件

| 审查项 | 最低条件 | 主要内容 |
| --- | --- | --- |
| 商务标形式审查 | 商务标 OCR 完成 | 完整性、一致性、签字盖章日期、报价合理性、分项报价表 |
| 偏离项目审查 | 商务标 OCR 完成 | 检查商务偏离表中的 ★/△ 响应；技术标完成后重跑可并入技术材料 |
| 商务标查重 | 商务标 OCR 完成 | 商务内容、分项报价及相关偏离内容查重 |
| 人员复用审查 | 技术标 OCR 完成 | 抽取商务标和技术标人员，人工确认后检查跨文件复用 |
| 技术标查重 | 技术标 OCR 完成 | 对技术标文档进行内容查重 |

执行方法：

1. 勾选需要执行的审查项。
2. 点击批量执行按钮。
3. 等待卡片状态由“执行中”变为完成或异常。
4. 查看“项目审查总览”。
5. 点击“查看结果”或“查看审核详情”进入结果审核。

不要在同一个项目任务运行中连续重复点击执行按钮。

## 8. 结果审核和人工复核

### 8.1 查看结果

1. 进入“结果审核”。
2. 选择正确的项目。
3. 使用左侧结果类型、文件和审查项筛选。
4. 在问题卡片中查看投标人、审查项、系统结论、对应文件和页码。
5. 使用上一条、下一条或跳转功能切换问题。

### 8.2 PDF 定位

- 点击预览或页码可打开对应 PDF 页面。
- 高亮框表示系统识别到的证据区域。
- 可输入页码跳转，也可放大、缩小。
- “下载 PDF”用于下载原始文件复核。

高亮位置只是辅助定位。如高亮偏移、文字不清或页码异常，应下载原 PDF 人工确认。

### 8.3 问题处理

对每条结果可执行：

- “忽略此项”：人工确认没有问题，导出时按通过项显示为绿色。
- “确认保留”：人工确认问题需要保留，导出时按不通过项显示为红色。
- 未处理：保持系统原始状态。

在确认前应检查原 PDF，不要仅依据摘要文字判断。

### 8.4 人员名单确认

人员复用需要人工确认名单：

1. 打开“人员抽取确认”。
2. 按投标人和文件检查姓名、角色和页码。
3. 修正识别错误；可添加或删除人员。
4. 保存草稿。
5. 点击“确认名单并查重”。
6. 确认完成后查看跨文件重名结果。

相同姓名不必然是同一人，最终仍需结合单位、岗位和证明材料核实。

### 8.5 商务标识别内容修正

对于支持人工编辑的商务审查项：

1. 根据右侧 PDF 原文检查系统识别值。
2. 修改识别内容。
3. 仅需暂存时点击保存。
4. 需要更新结论时选择保存并重新审查。

### 8.6 偏离状态修正

★/△响应判断有误时，可在对应问题中修正人工状态并保存。修正后刷新结果，确认问题数量和展示状态已经更新。

## 9. 报告导出

### 9.1 Word 报告

1. 完成必要的人工复核。
2. 点击导出入口。
3. 检查导出项和已选问题数量。
4. 点击“导出 Word 报告”。
5. 下载完成后打开 Word 复核。

Word 报告主要包含：

- 项目名称和“项目审查报告”标题；
- 采购人、采购代理机构和查询时间；
- 投标人名单及联系人；
- 源文件属性表；
- 审查总览、对应文件和审查明细。

源文件属性表展示标题、作者、主题、关键字、创建程序和制作工具。字段为 `-` 表示源 PDF 没有填写该元数据，不表示系统漏读，也不能据此认定文件异常。

属性表使用横向页面，后续正文恢复纵向。若使用第三方办公软件打开后版式不同，建议使用 Microsoft Word 或兼容性较好的 WPS 版本检查。

### 9.2 JSON 导出

JSON 用于结构化留档或后续系统处理。普通业务人员一般使用 Word；JSON 不宜直接作为正式报告阅读。

### 9.3 导出状态规则

导出全部审查结果；忽略项标为通过（绿色），保留项标为不通过（红色），其余保持原状态。

旧报告不会随系统中的复核结果自动变化。修改或重审后应重新导出，并按时间或版本区分文件。

## 10. 项目管理注意事项

### 10.1 防止项目串文件

1. 每个项目使用唯一名称。
2. 不把另一个项目的 PDF 放入当前上传文件夹。
3. 每组商务标和技术标属于同一家单位。
4. 上传完成后先核对文件绑定，再开始 OCR。
5. 导出前核对报告首页投标人名单和“对应文件”。
6. 系统拒绝同名项目时，不要通过修改少量空格等方式规避，应使用正式项目编号命名。

### 10.2 删除项目

删除操作前应确认：

- 当前选中的项目名称和编号；
- 审查报告已经下载归档；
- 数据管理员已经确认是否需要保留原始 PDF 和结果；
- 删除不会影响仍在使用的项目。

项目删除属于高风险操作，应由指定人员执行。

## 11. 管理员操作

进入“用户管理”后可执行：

1. 创建账号并设置用户名、初始密码、展示名和权限等级。
2. 修改展示名或权限等级。
3. 停用、启用账号。
4. 重置用户密码。
5. 删除不再使用的账号。

系统不允许删除当前登录账号，也会阻止降级、停用或删除最后一个启用的管理员。

管理员应定期：

- 清理无关账号；
- 避免多人共用同一账号；
- 为新账号设置临时强密码并要求及时更换；
- 检查异常登录锁定情况；
- 不在聊天或普通文档中传递生产密码。

## 12. 常见问题

### 12.1 页面显示“API 连接失败”

点击顶部“刷新”。仍失败时记录发生时间和页面提示，联系管理员检查前端、后端和网络。

### 12.2 OCR 长时间没有完成

先查看当前文件和页码是否仍变化。若完全停止，刷新项目状态后使用当前阶段的继续按钮；不要重新创建同名项目。

### 12.3 为什么 PDF 没有作者信息

作者是 PDF 的可选元数据，不是正文中的签字人。扫描仪、打印转换或隐私清理都可能不填写作者。创建程序和制作工具也只能作为线索，不能单独证明文件制作关系。

### 12.4 投标人名称不正确

优先检查上传文件夹的公司目录名、商务标文件名及商务/技术标配对。若绑定错误，不要继续审查，应联系管理员修正或重新创建正确项目。

### 12.5 报告内容还是旧结果

已下载的 Word 不会自动更新。完成重新审查或人工处理后，需要再次导出新报告。

### 12.6 PDF 预览或高亮失败

尝试切换页码或刷新页面；仍失败时使用“下载 PDF”查看原件，并把项目名、文件名和页码提供给管理员。

### 12.7 首次分析较慢

部分模型按需加载，第一次调用可能包含模型预热时间。后续同类调用通常会更快。

## 13. 运维人员快速检查

业务用户通常不执行本节命令。运维人员可按以下顺序检查：

```bash
docker ps --format '{{.Names}}\t{{.Status}}\t{{.Image}}'
curl -fsS http://127.0.0.1:8080/health
curl -fsS http://127.0.0.1/
docker exec xtjs-vllm python3 -c \
  "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/health').status)"
```

预期看到以下三个容器处于运行状态：

- `xtjs-frontend`
- `project-xtjs`
- `xtjs-vllm`

常用日志：

```bash
docker logs --tail 200 project-xtjs
docker logs --tail 200 xtjs-vllm
docker logs --tail 100 xtjs-frontend
```

标准后端与 vLLM 启动方式：

```bash
cd /root/project_XTJS/project-XTJS
docker compose \
  -f docker-compose.yml \
  -f docker-compose.gpu.yml \
  -f docker-compose.lean.yml \
  -f docker-compose.vllm.yml \
  up -d
```

前端应使用结题发布镜像启动并加入 `project-xtjs_app_network`。具体构建、迁移、备份和回退步骤以《部署指南》和结题版本部署清单为准。

## 14. 故障反馈信息

向管理员反馈问题时，至少提供：

1. 发生时间；
2. 登录账号，不提供密码；
3. 项目名称和项目编号；
4. 页面名称；
5. 文件名和页码；
6. 操作步骤；
7. 页面完整错误提示或截图；
8. 是否可以稳定复现。

不得通过普通聊天工具发送数据库密码、JWT 密钥、OSS 密钥或完整敏感投标文件。
